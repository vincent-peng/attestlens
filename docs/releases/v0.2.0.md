# AttestLens v0.2.0

**Release date:** 2026-04-19  
**Theme:** Scanner credibility release

## Shipped

- Hardened URL scanning with guarded outbound fetches, redirect validation, and deterministic JS byte budgeting
- URL-capable CLI `audit`, MCP URL scan tool, and first-class PDF reporting
- Validation corpus runner for 9 public targets with a tracked findings-quality log
- Stack-specific repo checks for Supabase, Firebase, Stripe, Clerk/Auth0, and platform-secret exposure
- Report-target sanitization so shared artifacts do not leak signed URLs or absolute local paths
- 125 passing tests across CLI, MCP, scanner, mapping, reporting, validation, and stack-check paths

## Validation outcome

- 9 targets were logged in the validation corpus
- 7 completed successfully on the final clean pass
- 2 (`supabase.com`, `clerk.com`) intermittently failed due live-site fetch blocking during the final rerun
- OWASP Juice Shop produced the consultant-facing sample report used for this release

See [VALIDATION-LOG](../VALIDATION-LOG.md) for target-by-target notes.

## Known limits

- CDN and bot-protection layers can intermittently block live-site scans, which currently surfaces as URL fetch failure
- A small set of passive URL heuristics still need tuning:
  - `AL-KEY-011` can still be noisy on documentation-heavy bundles
  - `AL-INFRA-006` is too eager on some non-WordPress properties
  - Firebase/Google API-key semantics still overlap
- Passive URL scanning is not a pentest substitute; Juice Shop still demonstrates misses for deeper exploit-class vulnerabilities
